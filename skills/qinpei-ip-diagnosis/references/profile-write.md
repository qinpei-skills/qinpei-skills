# 画像写入细则（诊断完成后执行，用户级＋共享画像按授权写）

> **什么时候读这个文件**：完整诊断完成（含劝退结论）后。**先征得学员明确同意再写**；拒绝保存不影响诊断交付，也不再追问。拒采暂定版不写画像。写完一句话带过，不念文件内容。

---

**写之前先确认**："我把你的定位存下来，以后你再来、或者用其他功能，我就不用重新问你了，好吗？"（学员同意才写；这是必做动作，但要说一声。）

## ① 用户级记忆（`~/.workbuddy/MEMORY.md` · 让画像在任何会话里自动被读到）

- **先 Read 整个文件**，找到 `<!-- qinpei-profile:start -->` 与 `<!-- qinpei-profile:end -->`。
- **已有标记块** → 只替换块内内容，块外**一个字都不动**。
- **没有标记块** → 追加到文件末尾（不插入、不改动任何既有内容）。
- 写入内容（精简版，控制在 15 行内）：

```markdown
<!-- qinpei-profile:start -->
## 我的业务定位画像（沁珮技能包通用 · v5）
- 你是谁：做大健康5年，主营中草药保健品
- 做什么：帮产后妈妈调理气血和身材
- 帮谁：产后妈妈
- 解决方案：中草药+外治法的调理方案
- 主赛道：女性健康（产后·更年期）
- 定位模式：教练型为主 + 专业身份型为辅
- 你凭什么：结果背书——服务过100多个产后妈妈
- 一句话业务定位：用中草药+外治法，解决产后妈妈的气血和身材问题
```

（上面是模板示例——写学员的真实内容，不照抄示例数字。**旧版 v4 画像字段（四要素/IP类型）继续兼容可读；v5 新写按本模板。**）

## ② 共享画像（命名空间优先 · 详细版，供沁珮其他技能包共享）

**路径判定（先读后写，只写一处）**：
1. 已存在 `~/.workbuddy/skills/@indiv-qinpei/qinpei-profile/我的画像.md` → 写这里。
2. 否则已存在 `~/.workbuddy/skills/qinpei-profile/我的画像.md` → 写旧位置，保持兼容。
3. 两处文件都没有，但命名空间 `qinpei-profile/` 目录已存在 → 在命名空间新建。
4. 以上都不存在 → 在旧位置 `~/.workbuddy/skills/qinpei-profile/我的画像.md` 新建，供后续共享。🔴 不同时写两份，不删除旧副本。

- 文件**已存在** → 只增量更新本包负责的定位字段（补三问、赛道、模式、定位、过程背书等），**不删除学员原有内容，不覆盖其他技能字段**。
- 学员说"重新填/重新来"也只更新本包负责字段，并保留一条旧定位历史（日期＋旧一句话业务定位）；不整份覆盖。确需删除某字段时必须再次单独确认。
- 文件**不存在** → 按 qinpei-profile 标准格式新建（基础信息/引流钩子/风格偏好/文案类型偏好/免打扰设置），未知字段留空，不代编。

## ②.5 劝退档案（v4.1.0 沿用 · 学员被劝退时写这个，不写定位画像）

学员走了 SKILL.md 三.4 劝退路径 → 画像**不写定位八段**，改写**劝退档案**。四处字段一个不许少：

```markdown
<!-- qinpei-profile:start -->
## 我的IP画像（沁珮技能包通用）
- IP状态：**暂缓IP**（2026-XX-XX 诊断结论）
- 劝退原因：【一句话，来自诊断时的具体判定，如"业务未跑通：无稳定客户、无内容积累"】
- 三个月要攒的三样东西：①【与学员共同定下并确认过的】②【】③【】
- 复查日期：【绝对日期，如 2027-01-20——当天 + 3 个月】
<!-- qinpei-profile:end -->
```

- **复查日期必须写绝对日期**（当天 + 3 个月），🔴 禁止只写"三个月后"——没有日期，三个月后谁也无法触发复核。
- 三样东西必须是**可验收的具体项**（"3 个稳定客户"可以，"把业务做好"不行）——这与 SKILL.md 三.4（4）的劝退前必做联动。
- **共享画像（②处）同步**：在对应文件加一行"IP状态：暂缓IP（复查日期 X）"，不建详细定位档案。
- **复访识别（与 SKILL.md 〇节联动）**：学员之后再来做诊断，读到「暂缓IP」标记 → 先复述劝退原因和三样东西、逐项验收，全过才进正常诊断；缺哪项先补哪项。
